# Native lifecycle wiring and bounded author edits

New `skill_rsi_native_lifecycle.py` binds a trusted API factory to the existing supervisor and isolated perception worker. It preserves a single setup/seed, explicit exception class mapping, API false values, and main-thread identity. Public task_spec contains only instruction/roles. Perception receives only source text, RGBD and calibration; missing/abnormal worker results stop the session rather than being silently treated as detection failure. Close never performs settle, render or evaluation after a failed/unknown call.

Ten focused native-lifecycle CPU tests and six small-edit tests pass. One test runs the real restricted skill process, API supervisor process and restricted perception process together with a synthetic backend; it is not a robot rollout. Native SimTimeout is mapped explicitly to a budget failure, unknown exceptions remain infrastructure errors, and timed-out calls have unknown outcomes and cannot be retried. The first integration fixture used the wrong detector parameter name; the exact upstream validator rejected it. Its failure and diagnostic are retained; only the fixture signature was corrected. A pre-launch source check also corrected an import of a nonexistent helper to the existing bounded resource reader/gate.

The production hook calls the fixed native API/monitor, no-denoiser renderer and fixed CLIP assignment, retaining CLIP timing. It is not yet qualified with SAPIEN. Its physical factory accepts only separately frozen published-source configurations and owns its GPU lock; no such configuration is currently supplied. Generated skill execution is not authorized. Still needed before a physical candidate comparison: a trusted evaluator-only completion channel, common full-episode wall/code-line accounting, process-group cleanup including any active perception child, and matched native-input/effect validation. Existing APISupervisor limits and skill CPU prototype deadlines must not be silently treated as the original240-second task execution contract. Initialization failure may occur before native setup returns its object; process exit evidence remains necessary. This is a useful wired CPU path, not a complete qualified robot sandbox.

`skill_rsi_small_edits.py` exposes read_lines/edit_lines/finish. Changes require current file SHA and exact slice SHA, remove at most24lines and insert at most1600UTF8bytes, with no automatic indentation/newline/syntax repair. Original versions and refusals are retained. There is no whole-file tool, but this byte cap does not guarantee1024token envelope completion. Three additional transport tests pass, covering structured message history and failed-call accounting. These are deployment interfaces available equally to all future compared authors, not claimed paper innovations.

Independent offline protocol `skill-rsi-small-author8-20261106-0245` uses the same fixed Qwen30BMoE/32K/1024 and original public/inherited resources, starting a fresh workspace. It has at most8newgenerations, no robot/VLA calls, and no candidate execution. Its new allowance is unrelated to the prior closed6used+2canceled proposal. The task remains a proposed natural two-to-three-bowl extension with old two-bowl retention; no old partial edits or validation feedback are provided. On incomplete/error output, close and cancel remainder; do not extend or repeatedly rerun the editor configuration. A complete artifact still requires static review, execution integration, independent task budget and strong matched from-scratch/inheritance/feedback controls.
