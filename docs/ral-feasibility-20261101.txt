预算约束下基于 RSI 的 VLA–Harness 持续学习：可行性评估与收敛计划
日期：2026-11-01；性质：研究决策，非论文结果或录用承诺。

结论

有条件继续，尚不足以支撑一篇 RA-L。已有非零的冻结 VLA 能力和可执行环境，但共同后端上接受的持久共享更新为 0，更新后的遗忘未测，严格 RSI 证据为 0。当前最重要的实验不是扩大轮数，而是证明存在可学习的有效共享更新和真实的探索—保留成本权衡。若这一前提不成立，不做预算分配器的大规模实验。

RA-L 评审说明重视原创且有意义的机器人研究结果，成熟度不必等同长篇论文，但质量要求并不因篇幅短而降低[1]。因此，“VLA+Agent+记忆+预算”组合本身不足以构成贡献。以下路线有投稿潜力，但是否足够取决于实验，不能现在保证录用。

一、只保留一个核心贡献

拟研究：在冻结 VLA 和语言模型的前提下，进化一个可迁移的预算分配程序，决定下一份计算/机器人交互预算用于生成新技能候选、探索当前候选，还是复测受共享更新影响的旧能力。

内层状态是共享技能/路由库 H、开发经验 D 和剩余预算 B；外层可修改对象是分配程序 A。固定模型提出 A 的版本更新；用重置的 H0、D0 在开发任务序列上比较，只有外部固定选择器认可才保存 A。A 不能修改评分器、提交门禁、模型权重或预算上限。一次普通技能改进不是 RSI；只更新分配器参数也可能只是常规元学习，必须与同特征、同训练成本的不自我修改分配器比较。

建议的有限动作集合为：提出一个共享候选、在当前任务上分配一个开发回合、在指定旧任务上分配一个回归回合、放弃候选或停止。输入仅包括实际执行得到的结果、成本、不确定性摘要和技能调用依赖，不允许隐藏物体位姿或最终测试反馈。候选的行为权限、生成器、观察和接受门禁对所有方法一致。

分配器需要学习的是哪些信号值得继续投入、何时先复测旧任务以尽早否决有害候选、何时把预算留给新的候选。可用开发目标是“随累计总成本变化的保留能力与新能力曲线面积”，并单列遗忘。仅靠额外调用得到更多成功不算收益。当前是算法提案，未实现或证明外层进化收益。

机器人相关性来自共享双臂技能的跨任务干扰、物理交互成本不同、运动规划失败与任务失败的区别。必须用真实 rollout 证明这些因素确实影响决策；不能只在抽象费用表或人为注入坏技能上证明。

二、与已有工作的边界

HCL 已提出冻结模型下的 harness 持续学习、历史能力保留和更新提交门禁[2]。本轮官方源码审计还发现它已有 cheap screening、候选排序和覆盖率检查[3]。因此“先小样本筛选，再复测”不新；不能把 HCL 简化为每次全量重跑的弱基线。

RoboRSI 已有结构化技能、局部修改、验证后复用[4]。技能依赖关系和受影响分支复测不是我们的独立贡献。其原生系统是代码/工具 Agent，与冻结 VLA 执行器须分表。

EmbodiedRSI 已有主动实验选择、信息价值和经验价值学习[5]。“根据价值选择下一次实验”不新。候选差异是探索与旧能力复测的联合分配程序本身持续改变，并能在重置执行器和经验后迁移；这只是待证差异，不宣称已完成全面新颖性检索。

还应防止把程序搜索或超参数调优包装为 RSI：新增同特征的小型学习分配器/上下文 bandit 对照，并给它相同开发序列与总搜索成本。若后者同样有效，删除“递归自我改进带来独特优势”的结论。

三、现有证据和本轮尝试

1. 固定50执行器：官方既定两任务各5个开发场景，全10完成；堆叠2/5，交接1/5。共186次VLA推理、9243原生动作计数、2801.341 GPU分配秒。仅开发面板，没有独立最终测试或终态稳定性复测；1200 horizon 与原生 CLI 10000 不同。固定50是有效控制器对照，不是论文方法完整复现。
2. 原生 RPent / RoboRSI：固定本地模型适配已真实运行但失败；结果保留，不能据此声称复现论文报告的成功率，也不能以击败失灵实现证明我们优越。8B/30B任意工具循环、上下文或prefix反复调参停止。
3. 本轮 HCL：官方 V1 分支提交 a6e5a01536ac8d42ca28f0a82efa223869c8c48d，688文件 Git blob 校验一致；官方20个离线测试中18通过、2因可选 pycocotools 缺失跳过。未运行其完整论文数据流，不称数值复现。先复用其真实筛选/门禁逻辑，再显式适配 RoboTwin。
4. 本轮候选：共享有限技能规则接口支持观测EEF相对移动、夹爪操作，不能访问任意代码/文件或改VLA预测。一个真实Qwen提案产生两条零位移规则，被判无行为作用并拒绝。两个生成调用（一个结构夹具、一个自主提案），14753输入/242输出token，10.587生成秒、77.558 GPU分配秒。没有任务候选评测或持久更新。该提案只有初态观察，没有执行后因果证据，因此失败不能泛化为一切共享技能学习无效；也不能靠自动重试掩盖。
5. 物理接口资格与任务表现严格分开。首轮因新增数组相等比较错误在动作前停止，0推理/0动作；错误已修复，独立资格两任务均通过，各10个原生计数、测得0.010092m末端位移，合计102.284 GPU1秒、0模型推理，初态一致、子进程正常退出。详见同目录 report.json。人工规定的资格动作不计 Agent 成绩。旧失败源码和关闭预算保留。

四、比较矩阵与公平性

基础参照：冻结 LingBot-VLA fixed50。它回答是否有改进空间，不承担“分配器优势”的全部论证。
主要方法比较：
 A. 相同共享候选空间，固定顺序/固定探索复测配额。
 B. HCL 官方 cheap screening + guarded evolution 的共同后端适配。
 C. 强固定 VOI + 风险规则（与 EmbodiedRSI 机制相邻，未复用完整代码时明确称重实现）。
 D. 不自我修改的学习分配器，匹配输入特征与离线搜索成本。
 E. 拟议进化分配器，额外消融为冻结初始分配器、去掉历史风险信息、仅迁移分配器。

所有方法共用有效候选生成器、工具权限、模型、任务语言、场景、动作/推理上限、提交门禁和部署。HCL 的最低验证要求不得只为新方法放宽。若保守门禁要求候选最终经过完整检查，则新方法只能通过更早否决坏候选、分配探索或减少无益搜索节约成本，不能把跳过必要验证当收益。若门禁固定成本占绝大部分，分配器可能没有可优化空间，这本身是停止信号。

两个实验层次要分清：固定候选集合的离线分配诊断只检验选择机制；在线闭环让所有方法用同一候选生成机制并按实际调用计账，才检验持续学习。不把前者当在线算法成绩，也不要求不同在线经历下出现完全相同候选文本。

成本包含候选生成、分配程序自改、筛选、拒绝、失败、辅助调用、回归与外层选择。保存token、GPU分配秒、VLA调用、原生动作计数等成本向量。主约束/换算系数须在主实验前固定并报告敏感性，不能事后选有利口径；原生动作计数不是物理tick。独立最终测试不反馈Agent，评估计算另列且各方法一致。

五、分阶段计划和止损条件

未来48小时：完成现有资格与账本审计；把本轮负提案作为正式负结果。将HCL官方排序/门禁对接共同评估格式，先做无需模型调用的语义对照。仅在接口物理资格通过后，冻结包含已用提案在内最多4个候选的先导；下一提案需使用预定抽样的执行反馈而非只看初态，禁止按效果挑截图或成功种子。先导总episode上限50–70只是设计量级，尚未冻结，不可直接启动。

第1–2周：完成两任务的有益候选可行性、更新前后全旧任务面板和另行预定的未见验证。没有候选时不浪费物理评测。必须至少出现一个真实有行为作用、在新验证上获益的共享候选；还须观察到自然候选之间的收益/保留/成本差异，不能手工制造遗忘。若有限先导无收益，停止该规则空间，最多一次基于真实失败证据的能力/grounding审计；不能无限换prompt。无可优化权衡则不启动分配器课题主实验。

第3–4周（前置通过才开始）：冻结4任务、至少3个任务顺序的开发实验和独立场景划分；任务按公开技能覆盖选取而非按成功率筛。比较B/C/D/E的等总成本曲线，A/fixed50作为参照。先以先导方差决定样本量，再冻结主协议，避免先定600episode自动跑。将任务序列作为主要独立单位，不把同一轨迹多个chunk当独立样本；报告配对差值与区间，避免微小样本的显著性宣传。

第5–6周：只迁移分配器版本，重置执行器和经验，测试未见任务组合/顺序。比较新能力增长、旧能力保留、成本曲线面积、平台期与验证—测试差距。报告自改成本摊销前后两种视角，不能只报预训练完分配器后的便宜推理。若等预算收益或单独迁移不成立，承认方法无优势/只为任务记忆，不继续宣称严格RSI。

第7–8周：通过前述证据门槛后才考虑少量有人监护的双臂真机验证及写作。当前RoboTwin夹爪实验不能宣称灵巧手结论；G1、手指控制、VLA权重RL和多模型扩大测试不作为首篇必要模块。真机需单独有人执行，不自动驱动。无需为了填满GPU而训练无关模型。

六、RA-L的内部继续条件（不是期刊官方录用门槛）

至少具备：可信且不失灵的主要基线；真实的共享更新与旧能力保留结果；等总成本优于最强固定/学习分配对照；迁移仅分配器仍有效；机器人交互因素的机制消融；清晰失败边界和复现材料。先导一两个成功、接口通过、模型变大、一次改进或参数重调均不足以替代这些证据。

如果只能得到更省验证的固定规则，可改为更窄的机器人harness验证方法，但仍需新机制和强HCL筛选对照，不能自动认定够RA-L。如果没有稳定有效共享候选，则冻结本方向的算法主张，保留基线/部署结果供后续研究，停止继续堆系统模块。
