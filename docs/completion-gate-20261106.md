# Trusted completion gate and independent author choice

`skill_rsi_completion.py` adds an owner-only completion gate. A typed receipt describes actual child exit, pending API operations, transport/deadline/render errors and normal return. It is not a model-issued capability or a cryptographic receipt. The trusted owner must construct it from observed process state. No evaluator method is added to the public API. Valid completion preserves settle(2 seconds) then native scorer ordering and stores the score in private output; the returned acknowledgement has no score. Failed/unknown completion consumes the attempt without invoking settle or scorer. A settle error or elapsed deadline prevents scoring; no retry is offered. Eight focused synthetic tests pass, including seven invalid-receipt subcases. No candidate code or robot was executed.

This gate is not yet wired to the native supervisor's separate control channel. It does not interrupt blocking C++ calls: the outer owner must enforce a deadline and clean up its process tree. Full native wall/code-line accounting, process-group/perception cleanup, C++ stderr monitoring and a published-source matched physical qualification remain. Do not claim the complete sandbox or episode boundary is done. Old frozen runners were not modified. Upstream episode.py has a finally-block fallback scorer call; omitting such a call after transport/timeout is an explicit conservative deployment difference, not identical original error semantics.
