# Contingency: a common VLA execution contract

This is a design draft, not a launched protocol. Keep the paper question: under equal total learning cost, can an evolved allocator improve new-task learning and old-task retention, including allocator-only transfer to a reset executor and memory?

## Decision rule

The single qualified30B RPent attempt is now closed with zero actions on both tasks; each repeated the identical MEMORY.md read29times. The stop condition is met. Stop this model/interface configuration. Preserve both 8B and 30B adaptations separately; neither is a faithful reproduction of the paper's original model. Do not claim superiority over a broken local baseline. No further model download, prompt search, additional calls on these scenes, or manual motion rescue.

Before new online comparisons, define one shared execution contract for every VLA-harness arm. Keep the native LingBot model, task+seed language, RGB/state, scorer, horizon and task split fixed. Expose a bounded VLA chunk execution, fresh observation and termination. A frozen harness can implement the same direct VLA behavior as the existing VLA-only control. A model-controlled harness must make its own decisions; do not inject an action after a read-loop failure. Arbitrary filesystem browsing and dense geometry dumps are not needed for this reduced interface, but removing them is an explicit common-backend adaptation, not a native RPent result.

## Demonstrate a real editable capability before allocator experiments

The first finite paired executor diagnostic should test whether changing a small, predefined observation/replanning schedule changes actual executed VLA actions and outcomes. The previous `lingbot_act(prompt=...)` input is ignored and cannot be an editable parameter. Freeze the candidate schedule set and trial budget before measurement; retain failures and do not screen for successful seeds. If behavior is invariant or all candidates fail, do not proceed to claims about learning or forgetting. Diagnose the frozen executor or narrow the task scope using a predeclared development screen, reporting all exclusions.

Only then permit a persistent task/shared harness update. Save the exact candidate, old and new replay-free execution results, compute and model call costs, and rejected candidates. A retained old version alone is not measured retention: a real shared update must be tested on old tasks.

## Fair controls and strict RSI claim

Compare static VLA-only, fixed harness, uniform allocation, a strong fixed value-of-information/risk allocator, and the evolved allocator. All allocator arms use the same candidate generator, observation features, execution contract, memory capacity and acceptance gates. Charge generation, failed compilation/execution, screening, validation, old-task rechecks, and allocator evolution. Report model tokens, simulator/VLA calls, GPU time and wall time separately before choosing any scalar exchange rate.

Publish native-source reproduction attempts in a separate table. Any RPent/EmbodiedRSI-inspired reduced-interface implementation must be called an adaptation/reimplementation and checked against the paper's actual mechanism; do not attach the paper name to an arbitrary fixed harness. Include an original-backend reproduction only when genuinely reproduced. Avoid cross-dataset PI0 comparisons.

A useful task-learning curve is insufficient for strict RSI. Transfer only the evolved allocation procedure to a new task sequence with reset task harnesses and experience; compare it against the original improver at equal total cost. Independent final-test feedback is inaccessible to every improving agent. The 600-episode outline remains a draft.

## Failure paths within the same topic

- No effect from harness schedule candidates: the editable surface is ineffective; correct the execution binding before more evolution calls.
- New-task gains but old-task loss: analyze whether targeted revalidation detects regressions at less cost than full replay; do not relabel frozen-library preservation as forgetting prevention.
- Gains disappear after charging evolution: report a negative result at that budget, then test a predeclared amortization range on new sequences; never hide warm-up costs.
- Gains disappear when only the allocator transfers: claim task-specific harness optimization, not strict RSI.
- Both fixed and evolved rules saturate: use proposal diversity, duplicate rate, accepted-update rate and remaining headroom to distinguish executor ceilings from allocation failures. Do not extend parameter searches indefinitely.
