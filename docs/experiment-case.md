# 预算约束下基于 RSI 的 VLA–Harness 持续学习：可证伪实验论证

状态：**DRAFT，2026-10-29。未启动此方案的模型调用、学习轮次或仿真实验，未冻结执行预算。** 本文件不改动现有已关闭协议。正式启动需把模型、VLA、工具、任务/场景清单和预算全部写入独立 manifest 并计算哈希；这是执行前工程步骤，不要求再次向用户索取已授权的实验权限。

## 1. 论文究竟要证明什么

建议核心问题：**固定模型的机器人系统持续学习新任务时，有限试验既要获取新能力，也要确认共享 harness 更新没有损害旧能力；能否让 Agent 从历史更新中学会这两类试验的预算分配规则，并让该规则迁移到新的学习序列？**

候选方法只开放一个小模块：`select_experiment(evidence, candidates, remaining_budget)`。输入为许可的执行历史、候选变更的依赖范围、已有成功/失败、观测噪声估计和剩余预算；输出为下一项新任务试验或旧能力复验证及其有限配额。规则以版本化代码/配置持久保存。任务 harness 可以更新，但冻结 VLA、Qwen、解析工具、成功评分器、硬预算、提交门禁及最终测试。首版不同时引入模型训练、任意工具生成和大规模记忆重写。

机制假说是：共享路由/记忆/技能的改动风险不均匀，均匀复测会浪费预算，完全不复测会漏掉退化；只有新任务信息价值也可能忽略旧能力。候选分配器利用实际受影响的调用分支、历史边界条件与证据新鲜度，把预算花在最可能改变接受决定的试验上。此机制必须通过“固定选择器也看到相同特征”的对照来检验，不能靠额外信息取胜。

论文不以“Agent 自己改代码”作为充分创新，也不以“回归门禁”“主动选试验”“按未来价值选记忆”作为首创。可成立的贡献是：**把新能力收益和历史能力风险放在同一可审计预算中，演化分配规则，并以共同起点的规则迁移证明学习效率收益。** 是否优于固定规则仍未知。

## 3. 必须先跨过的真实性门槛

1. 原生全系统：Planner–Engineer–Reviewer 及其上层组织、持久会话/图像/工具响应/压缩均可追踪；所有辅助模型调用走固定本地 Qwen。`run_rollout` 单执行器、`ROLE_SESSION=0` 无状态替代不叫默认完整 RoboRSI。并行源码审计发现 README 的 frozen-eval 描述与 runtime_mode/run_role 有差异：实际 evolve/frozen 都保持持久会话，episode_gate 的候选门控子进程才显式无状态；不能从 README 推导出可以跳过本地 CLI 适配。
2. 真实物理执行：有自主工具选择、实际机器人动作、环境步数和终态评分。完整闭环即使失败也保存。模型权重加载、路径正确、RPC import、人工脚本执行只属资格/诊断。
3. VLA 真正参与：主试验含 VLA 调用次数、动作步占比和调用任务分布；全靠解析工具成功不能支持 VLA-harness 协同的结论。VLA-only、解析-only 仅作底层可达性诊断；不得用人工提示逐步带领 Agent 当成绩。
4. 可学习且有干扰：至少有旧任务已具备非零能力，新的共享 harness 更新有可能改变旧任务实际调用。仅冻结旧技能文件只能证明字节未改，不能证明调用、参数或全局记忆未发生遗忘。旧能力应通过完整 Agent 自主选择技能复测。
5. 失败即定位到层：传输/上下文/schema、感知、规划、VLA 控制、候选更新、提交门禁分别计数。基础控制始终失败时，不继续把算力投入高层 RSI 比较。

现有 RPent 16K 开发协议已关闭：200 次调用、2 个开发尝试、0 原生动作；32K 资格已关闭：21 次堆叠调用，另 2 次先前 canary，交接未启动，0 动作，179 次剩余额度取消。它们是本地模型适配的负结果/部署限制，不能删除、补跑为同协议、当论文方法失败率，或折算成最终成功率；`retention_after_update=null`，不能写成零遗忘。新方案使用独立 ID 和新预算。

已有独立 VLA-only 开发事实也要保留：`rpent-vla-only-20261028-0250/report.json` 中固定 LingBot 根据当前图像生成动作，堆叠 seed100000、交接 seed100001 各执行 600 个原生动作，均未完成，0 Qwen 调用。它证明存在真实动作路径及该上限/场景下的失败；每任务1场景不证明 VLA 普遍无能力或任务不可达。该协议关闭，不延长或补跑。600 步 VLA-only 与旧高层 10000 action-cap 不能混表排名。

## 4. 可证伪假设与最小对照

| 假设 | 必须看到的证据 | 否证/不成立的情况 |
|---|---|---|
| H1：预算分配有效 | 相同总预算下，全已见任务平均成功率–预算曲线 AUC 优于最强固定分配器；旧任务退化不超过预设实用界限 | 仅训练场景提升；收益在包含自我修改/筛选费用后消失；固定规则同样好 |
| H2：改进器可迁移（严格 RSI） | 只转移分配器版本，在相同初始 harness/经验/模型、未用于选择的新序列上，后续学习 AUC 提高 | 只有继承更多技能/记忆才提高；相同任务重排有效而新任务无效；规则必须继续看测试结果才能有效 |
| H3：保留来自有效复验证 | 同预算与相同候选来源下，风险定向复验证降低误提交，保持旧任务，同时留下更多新任务学习配额 | 只是复测更多；固定依赖启发式同样好；保留所有旧文件导致退化从未可能发生 |

最小主比较：

| 代号 | 任务 harness | 分配策略 | 用途 |
|---|---|---|---|
| S | 冻结 | 无学习 | 基础能力和漂移控制；只报实际成本，不强迫烧完预算 |
| U | 可更新 | 固定均匀分配，旧任务与新试验按预注册配额 | 排除多轮训练本身 |
| F | 可更新 | 固定成本归一化 VOI + 依赖风险启发式，看到与 E 完全相同的特征 | 强主对照；公式/阈值在开发集固定 |
| E | 可更新 | 与 F 同初始化，允许有限持久更新分配器 | 本方法 |

E 与 F 的任务候选生成器、harness 表达能力、记忆容量、可写权限和提交规则相同。E 自我修改消耗同一总预算；F 可以把省下的预算用于更多合法试验。不使用“等 rollout 数但 E 额外免费优化”的比较。

固定门禁不得偷偷随分配器一起放宽。首版采用相同的必要覆盖下限、接口有效性检查和新旧配对试验提交规则；分配器只在满足共同下限后决定追加哪项证据。具体下限与接受规则在先导前冻结。有限复测通过只表示已检查场景未观测到退化，不构成全分布无遗忘保证。若在同一门禁集上反复提案并挑赢家，会过拟合门禁；故记录累计试探次数、轮换开发复测样本，保留隔离审计，并把所有失败候选费用计入。若将来声称统计风险上界，必须另行采用适应性检验有效的规则及其假设；本首版不作该理论保证。

先只实现 E 相对 F 的一个差异，再扩展消融：E-freeze（后期冻结分配器）、E-no-risk（不提供依赖风险特征）、E-uniform-retest（保留新经验选择但旧能力均匀复测）。若只能做一个消融，首选 E-uniform-retest；若 E 与 F 无差异，不并行堆加全部模块。任何完整 AdaHVLA/EmbodiedRSI 适配作为额外论文基线，不能把 U/F 冒充这些完整方法。

另做一次“共享候选池”诊断：冻结同一批由已授权开发产生的候选与历史，比较 F/E 选择；它只能隔离选择行为，不能替代在线结果，因为没有执行的反事实收益仍未知。

## 5. 统一后端与数据/权限协议

优先固定当前 RPent 官方 RoboTwin–LingBot 入口：`RLinf/LingBot-VLA-RoboTwin-EEF-ckpt1500`，revision `e727b46cd220b66981ea4d2fd9ba84adc189e2cc`，包括依赖的 qwen_base；逐文件证据在 `rpent-qualification-20261027/lingbot-model-manifest.json`。正式 manifest 仍必填：文件哈希、动作归一化、控制频率、action chunk、相机和语言接口；Qwen3-VL-8B-Instruct 全部权重/processor 哈希、上下文/输出上限、temperature、seed、框架版本；RoboTwin ae507381…、资产 c15cc97b…、机器人本体、初始化筛选、物理引擎、环境 horizon、工具 schema 与评分函数哈希。新机部署/资格未通过前，不视为可运行；VLA 字段不能以“pi0/LingBot 任意”启动。

本研究的统一数据包括固定场景/任务初始化、各方法可见的初始示范/记忆、受预算控制的新交互；不是随意拼接已有 pi0 训练集。已有 DexMimicGen pi0 的状态维度、场景和训练统计不与 RoboTwin 混表。若换 pi0，需单独适配、固定训练数据和新 checkpoint，并建立全方法共同起点。

使用四种可访问域：

- `D_learn`：Agent 可见，可主动选取；包括新任务学习与旧能力复验证。所有 reset、失败、复演和验收都扣适应预算。
- `D_select`：仅用于开发阶段选方法/阈值与冻结分配器；有限次数、独立种子。用于反馈的记录明确不再是最终测试。
- `D_curve`：由独立执行器重放已保存的各轮 harness 快照形成曲线；进化 Agent 不可读，最终方案冻结后才解封。不能根据曲线选择最优轮次再报同一批成绩。
- `D_final`：冻结后的最终新场景/组合/任务序列；路径、种子、评分器与反馈不可由 Agent 读取或修改。启动后无自适应人工改协议；允许的在线学习只在该序列独立的 D_learn 流里。

仅 seed 不同不等于实例独立：记录状态哈希、物体/纹理/语言生成器和家族；相同场景不得跨域。对无效初始状态用与方法无关的固定判定/补位规则，记录所有 reset 次数和理由。expert 可验证场景可行性，但该动作/轨迹不得泄漏给 Agent、不得作为 Agent 成绩。

共同权限：同样的初始技能和示范；同样的图像与观测；无真实物体坐标等额外 GT 输入；同样的写入目录、工具权限和记忆容量。原生系统若需要额外工具/人类知识，原生表保留，统一表须对所有方法开放或排除该比较。最终测试隔离用进程/文件权限和 API 边界，不只依靠 prompt 要求不看文件。

## 6. 严格 RSI 的“只移植规则”试验

1. 在元开发任务家族 A 上，以同一个初始分配器 F 和任务 harness H0 开始产生 E1、E2…，保存每次变更、提案/拒绝和全部成本。
2. 用独立的开发选择域 V 固定 E*，此后不根据正式迁移域 B 反馈再选择 E*。至少保留 E0、一个中期版本、最终版本，报告曲线而非只展示赢家。
3. 在 B 的每一条配对学习序列上复制相同 H0、相同初始经验 M0、同模型、同调用权限、同场景流与预算。仅分配器为 F 或 E*；不转移 A 中已学会的任务技能、轨迹、具体场景坐标或隐含任务答案。
4. 第一项确认实验冻结分配器 F/E*，但允许两边任务 harness 从同一起点学习；直接测“学习如何改进”的迁移。后续允许分配器继续更新，是另一个比较，不能代替此项。
5. 检查策略导出物：允许通用特征权重、可读规则/程序；限制体积，禁止嵌入任务答案、整段轨迹、模型权重和测试索引。保留可见经验的内容哈希与访问日志。
6. 两种成本口径都报：B 上相同部署预算的迁移效率；包含 A 上进化/筛选成本的端到端效率。若前者提高但后者暂不划算，只能主张可摊销收益，并给出达到收支平衡所需的新序列数量。

若 B 只是相同任务的新 seed，则只叫实例迁移；相同任务的新顺序只叫顺序迁移；使用新的任务家族才能支持更强的任务迁移。VLA 预训练可能见过 B 的任务，这不妨碍检验改进器迁移，但不得宣称 VLA 零样本新任务。

## 7. 预算账本与可核查指标

预算向量为 `B=(model_requests, prompt_tokens, completion_tokens, env_resets, control_steps, GPU_seconds, wall_seconds)`，任一上限触发即停止，不跨实验借额度。模型请求包括全部角色、感知、技能选择、反思、候选生成、失败重试、会话压缩；失败调用也计次。图像输入 token 按真实服务收据计。解析工具耗用环境步同样入账。分别报告模型分配时间和实际推理时间，不能把共享服务常驻时长误当每次推理成本。

将适应预算、独立评估预算、一次性部署预算分列，同时给总支出。离线查看/排序已有经验也消耗模型预算；人工写方法和软件调试不伪装成 Agent 自我改进。初始化搜索/验证失败不从成本中消失。

主要结局：预算利用率 `b=max_j(C_j/B_j)` 上全已见任务等权宏平均成功率 R(b) 的归一化梯形 AUC；预算节点预先固定。补充分别以环境控制步、模型 token、GPU 秒和真实时间为横轴，避免某个加权合成成本制造排名。S 的冻结能力曲线是常数参考，不把未用预算伪记为成本。

记录 R[t,k]：学完第 t 阶段后，冻结快照在任务 k 固定审计场景的成功率。最终平均能力为所有已见任务等权平均。旧能力下降报告 `max_{s<t} R[s,k] - R[t,k]` 的有符号值、非负遗忘值及相对“初次学会后”的差；不得只选择本来容易的旧任务。还报每任务成功/总数、配对成功转移、预算耗尽率、无动作率、无效提交率、回滚率、经验条数/字节/上下文成本，以及终态独立评分与 Agent 自报成功的差异。

保留率没有一个可在极小样本上可靠保证的数。5 个场景每次变化 20 个百分点；零观测退化不证明无遗忘。单比例给 Wilson/精确区间，方法差给场景配对差；主推断单位是独立完整学习轨迹/随机化顺序，不把同一进化历史下数百个 episode 都当独立重复。最终用学习轨迹层面的配对随机化检验与区间，同时展示全部轨迹；6 条轨迹是脆弱下限，争取 10 条。事先基于先导的配对方差/相关性做功效与精度模拟，不能在显著后停止扩样。

优先一个主比较 E 对 F 的 AUC；旧能力下降作为实用约束，严格迁移为第二层关键证据。若检验多项基线，预设层级/多重比较处理。不得通过挑时间点、任务子集或改变成本权重选出显著优势。

以下数值是待部署资格和吞吐校准后冻结的 **DRAFT**，不是自动启动授权额度，不补回已关闭协议。模型仍固定本地 Qwen；仅 lzgpu201 两张空闲卡。

### 两周先导

- 避免底座能力过低：先预注册一个只用于开发的最多6任务×3场景能力筛选，保留堆叠/交接，另外从共同底座支持的简单拾放/双瓶/容器任务选4项。筛选仅运行统一底层诊断，不看 E 的结果；固定相同 horizon、观察与初始化。若所有方法都接近零，先定位低层/分布问题；若某项太容易，则只能作为保留任务。筛选依据、失败任务和结果全部公开，正式任务清单在比较前冻结。这18个episode是新独立诊断协议，不重开旧600步协议，也不计RSI收益。每任务3场景仅作能力筛选，不构成可靠成功率估计。
- 资格阶段：两任务 `stack_blocks_two`、`handover_block` 各至少一条完整自主尝试，逐调用/动作对账；任何成功率都标“资格样本”。保留完整原生角色和工具。旧开发 seed 不进后续独立审计。
- 首个可归因比较：S/U/F/E 四种条件，3 个独立学习 seed，顺序均衡为堆叠→交接和交接→堆叠。每条学习轨迹最多 20 次适应环境启动（包括门禁复测），在初始/学一任务后/学两任务后评估两任务各 5 个固定、隔离的审计场景。上界 240 个适应启动 + 360 个审计 episode = **600**；S 不需消耗适应额度，实际数更低。
- 适应请求上限草案：每轨迹最多 2,000 个全角色模型请求、32M 输入 token、2M 输出 token、20 次环境启动、20×原生 horizon 控制步、12 小时墙钟，任一触发停止。每请求原有32K/输出上限不随方法增大；确切数值根据一次独立吞吐/原生工作量校准后、比较结果不可见时冻结。U/F 也可合法花完同样额度。
- 学到新任务后，重载持久技能及全部共享 harness，在相同审计场景重测旧任务。必须保存旧程序 hash 与整库路由/记忆 hash，区分未改程序与能力保留。
- 两周继续条件：真实动作/终态可靠；至少一个旧任务具备可测能力；至少产生一个可审计候选并经历接受/拒绝；E–F 的开发 AUC 差有正向且非单个场景的迹象，或清晰发现固定复测的预算浪费。5 场景不做优越性结论。
- 两周停止/转向条件：重复两次相同层部署失败无新证据则停止重复调用，改该层；各方法都无动作则暂停研究比较；VLA-only/解析诊断揭示不可达时先修统一底座；E–F 仍无区分则先做机制诊断，不把全部规模扩大十倍。

### 第3–8周主实验候选

元开发/主持续学习面板可先审计 6 个真实存在的任务：`stack_blocks_two`、`handover_block`、`stack_bowls_two`、`pick_dual_bottles`、`place_container_plate`、`place_dual_shoes`。任务名已在固定 RoboTwin 源目录确认，**是否可控、是否共享依赖和数据划分尚待资格审计；不是已选定的最终清单**。

严格迁移候选：`handover_mic`、`stack_blocks_three` 是相关家族迁移；`dump_bin_bigbin`、`lift_pot` 提供不同操作家族。前两项不能单独证明全新家族泛化。若统一 VLA 未覆盖，应在性能比较之前按能力/资产标准替换并重冻清单，不能因本方法得分差事后剔除。

建议最低主比较 U/F/E × 6 条独立学习轨迹 × 6 任务，每轨迹最多 60 次适应启动；4 个预算快照 × 每任务 10 个固定审计场景，总上界约 5,400 次环境 episode。严格迁移 F/E* × 6 条轨迹 × 4 任务，每轨迹最多 40 次适应启动，3 个审计快照 × 每任务 10 场景，上界约 1,920 次。冻结系统 S 作为较低成本参考；主要机制消融优先在开发面板做，不无条件把所有组合铺开。

总量约 7,320 次环境 episode，仅是容量规划。用先导的真实中位数和 P90 时长估算 `模型/仿真资源小时 + 失败余量`：若 episode 中位数 3 分钟，仅物理流程约 366 小时；若 10 分钟则约 1,220 小时，还未含模型与开发开销。因此两卡、1–2个月**有条件可行，不保证完成此上界**。若超时，先减少次要方法/重复检查点，保留主 E–F 对照、独立序列与最终测试；不能把有效样本缩成单次演示后继续主张普遍优越性。正式样本量由先导精度估计和可用资源共同一次性冻结。

第1周目标是底座自主动作与首个持久更新；第2周获得两任务学习–保留–成本完整链；第3–4周锁定一个机制、强固定对照与跨顺序；第5–6周做规则移植和独立曲线；第7–8周完成必要消融、冻结最终测试、稿件与局限分析。真实机器人只在有人现场、单独授权安排下补充，不是两周结果前提；RoboTwin 夹爪结果不能直接推广到灵巧手。

## 9. 饱和、过拟合与失败转向

预算内平台定义为开发选择域上连续 3 个固定等预算增量的改善都小于预设实用阈值（建议 5 个百分点或 AUC 0.03），且区间仍需报告。它是“当前预算/分布/模型下未观察到继续收益”，不是理论收敛；不据此改变最终测试预算。训练上升而独立场景不升才提示过拟合，需要区间和重复轨迹，不能从单条噪声曲线断言。

| 观测问题 | 最先做的区分实验 | 仍保持大方向的处理 | 禁止的结论/操作 |
|---|---|---|---|
| Qwen反复读文件/不动作 | 保存完整输入，检查上下文截断、工具schema、图像、会话历史；有限合约测试 | 修传输/压缩并独立资格；必要时未来换更强模型做同样完整矩阵 | 不提高单方法预算、强制动作后说自主成功 |
| VLA执行基本任务都失败 | 固定公开提示与动作接口，VLA-only可达性诊断 | 修归一化/控制频率；选择支持相同技能的共同底座 | 不把低层错误归因于RSI无效，不用专家成绩替代 |
| 只有新任务提升，旧任务退化 | 比较原技能直接调用与完整Agent路由；定位共享记忆/接口变化 | 演化复验证分配与依赖特征；保留固定提交规则 | 不把旧文件没改说成无遗忘 |
| E与强固定F无差异 | 共享候选池；比较选中试验、有效证据/成本；去掉自我修改开销看上界 | 若仅自改成本抵消收益，研究摊销阈值；若规则无收益，转固定风险预算器并降低RSI主张 | 不仅选弱随机baseline，不不断加模块凑差异 |
| 开发提升而迁移不升 | 仅规则移植、清空旧记忆、按家族隔离、限制导出体积 | 限制选择器复杂度；任务无关特征；报告适用分布 | 不把同任务新seed写成改进器普遍迁移 |
| 旧能力从不下降 | 检查是否实际上全部技能隔离，更新是否会触及共享router/memory | 在真实共享组件上自然产生竞争；增加共享任务组合 | 不人为破坏baseline制造遗忘 |
| 复测吃掉全部预算 | 固定门禁下比较覆盖/风险与误提交 | 重点研究预算化复验证，保持harness持续学习背景 | 不移除计费，不将验证当免费 |
| 新旧曲线都饱和 | 审核失败类型、控制上限、上下文/记忆容量；一次预注册诊断 | 收窄任务边界或研究经验压缩/饱和预测；另列扩展阶段 | 不无限试参数，不能自动解冻VLA/Qwen |
| 无源码/官方链长期卡住 | 标出缺失模块与最小实现差异，给每依赖固定排障时限 | 先运行可审计共同底座的F/E试验，并并行补官方复现 | 不把机制重实现命名为官方全复现 |
