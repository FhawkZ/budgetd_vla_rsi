# Evidence gates after the reduced controller pilot

The paper's target remains budget-constrained continual improvement of VLA harnesses, not local recovery and not tool-format repair. The reduced interface is a deployment diagnostic. Its ability to select real actions is necessary plumbing, not a contribution. Per-chunk LLM orchestration may be worse than a simple fixed executor: its observation and decision overhead must remain in the comparison budget.

The frozen fixed50 control is the minimum meaningful comparator. Do not replace it with the weaker exploratory controller as the incumbent and then claim a gain for rediscovering fixed50. A manually changed prefix, a model upgrade, a schema adapter, or returning to an already known successful configuration is not evidence that the improver has improved.

Before any evolution run, require:

1. **Stable execution and measurement.** Resolve native simulator RPC stalls using read-only diagnostic instrumentation in a separately frozen infrastructure protocol, not retries inside a task. Record last acknowledged action counts as lower bounds when an RPC has not returned. Do not label an incomplete simulator episode as a completed policy failure or a negative success-rate sample without disclosing censoring.
2. **Source-aligned baseline panel.** The pinned RPent suite contains50tasks/250cases. The two historical debug seeds are outside that list. Audit the exact published language, local assets/embodiment, source and horizon. `configs/official-focal-panel-draft.json` lists all five cases for each already chosen focal task; no outcome-based selection, backfill or seed replacement. This is not a launchable frozen protocol.1200actions differs from the native CLI10000default; use common limits and disclose any budget-limited adaptation. Official published cases used in development are excluded from independent final testing.
3. **Useful shared update.** The current three-tool scheduling surface may have insufficient useful variation. A candidate must improve over a functional fixed executor on development evidence while preserving nonzero prior competence. If the official focal panel reveals no useful improvement opportunities, diagnose checkpoint/task coverage and the editable harness's actual effects. Do not inflate budgets or repeat prefix/prompt search to manufacture progress. Any expansion to typed skill selection or experience retrieval requires a new common contract applied to all methods, with a clear mechanism-faithfulness table for adapted paper baselines.
4. **Fair allocator experiment.** Only then compare uniform allocation, strong fixed VOI+risk and an evolved allocator using the same candidate generator, evidence features, update permissions and acceptance gate. Separate allocation proposals from candidate-generation quality; include all proposal, failed-call, rejected-candidate and revalidation costs. Report utility-versus-cumulative-cost, not just final success.
5. **Strict RSI intervention.** Freeze the evolved allocator, reset execution harness and experience, and evaluate learning on new task sequences against the original allocator at equal total budget. This isolates improved improvement strategy from accumulated skills or memories. Independent final-test outcomes never enter the improver.

If learning saturates, first distinguish insufficient executor capability, no useful editable intervention, biased selection/evaluation, and exhausted budget. Expand only the diagnosed missing component; do not treat a flat curve as permission for unlimited parameter search. Until gates1–3 hold, persistent accepted updates, post-update retention and strictRSI remain unproven.
