# VLA 接口审计对创新验证的约束（2026-10-30）

本页补充 experiment-case.md，不改变已冻结实验或宣称方法有效。

## 实际可控量

固定 RPent 版本中 lingbot_act 的 prompt 参数只记录、不发送到LingBot。因此不能把“进化子任务prompt”当成已经作用于低层的创新；即使文本发生变化，只要实际模型输入/工具序列未变，就应按无效候选拒绝并计入生成成本。公共任务目标保持不可写。

该后端实际允许harness改变：何时调用VLA、调用多少个50-waypoint chunks、何时观察、如何在已有解析技能与VLA之间调度、怎样检索已有经验并产生后续工具选择。改变动作布局/归一化/原生成功评分不属于harness更新。每个方法共享同一工具权限和输入特征。

50是原生EEF waypoint数量，不是50个物理tick或固定50Hz。原生planner拒绝一个目标时，take_action_cnt仍可增加。必须分别记录提议、原生动作、物理步和成功；不能用1200动作计数证明1200次成功规划。历史账本不具备planner逐动作状态时明确缺失，不能补造。

## 对第一轮持续学习实验的要求

1. 首先具备非零旧能力的完整自主执行器；仅VLA有过单次成功不足以证明整个Agent有该能力。
2. 固定任务harness更新器/候选池、记忆容量、接口和提交规则，仅比较预算分配策略。主固定对照也看到依赖范围、证据新鲜度、旧任务风险和观测噪声等全部特征。
3. 新旧分配器影响的必须是实际试验选择和调用，而非无效prompt字段。保存实际工具trace/模型输入SHA，拒绝行为等价候选；失败/无效提案费用不豁免。
4. 旧能力复测调用完整Agent路由，不能只直接重放被冻结的旧技能文件。共享检索/路由更新有可能改变旧任务行为，才有保留实验的意义。
5. 在重置的执行器、经验和新任务序列上只转移分配器；若只有继承更多经验才获益，则不支持严格RSI。

## 基线与失败转向

论文主线仍是等总成本下的持续学习与能力保留。原生RoboRSI的本地Qwen工具幻觉作为复现限制单列，不能把其失败当作新方法优势。RPent与固定harness使用同一低层栈；先证明真实自主执行，再比较更新策略。

本次只做有限的语言对照：两个历史失败开发seed，保持控制与模型不变，比较原始公共full_description和环境原生语言。若初始观测不一致，语言因果解释失效；即使初态完全一致，两个场景仍不能证明广泛规律。若语言影响小，下一项应是只读规划/跟踪诊断或预声明任务覆盖，而非反复改prompt。若可用低层能力始终太弱，收窄到已支持的任务面板或更换共同公开底座，并对所有方法重新冻结，不能独自增强本方法。
